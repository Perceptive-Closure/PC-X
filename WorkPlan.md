## Scientific standards

- A complete finite PC contract keeps history admission, certificate equivalence, authority and controller observation distinct. Derive touch extensionally over all supported successors. Use complete atomic actions and the original freeze order. Costs evaluate worst positive-support branches of proper closing policies.
- Distinguish point identification, set identification, audit inaccessibility, inconsistent evidence and computationally unresolved cases. Verify witness well-formedness, certificates and minimum costs independently. A search failure or timeout is unresolved.
- Freeze every prospective experiment before opening outcomes. Record authorized interfaces, candidate classes, evidence, target, manipulation, controls, comparators, estimands, sample and inference rules. Record independently obtained query results and commit the prediction before the native measurement opens. Check the opening against a prior commitment when a separate custodian holds fixture assignments or seeds.
- Report raw counts, denominators, effect sizes and intervals when statistical inference applies. Exact exhaustive checks and deterministic native fixture tests have no sampling confidence interval. Retain negative, invalid, null and unsupported conditions with causes and impact.
- Validate source anchoring and epistemic limitations before claiming transfer. No estimate from these finite fragments by itself establishes the open T18 or T30 research program or the charter's aspirational scalable oversight separation.

## Repository and lifecycle

One private repository, [Perceptive-Closure/PC-X](https://github.com/Perceptive-Closure/PC-X), uses the `codex/pc-x-orchestration` branch for master records and a dedicated `codex/exp-xNN` branch per experiment. Each package lives below its own `EXPERIMENTS/EXP-XNN/` path. Use exact GitHub commit references for evidence. The parent maintains the live registry in [Path.md](Path.md) and issues acceptance after independent clean-checkout validation. No force-push or main-branch merge is authorized.

Each experiment is assigned to one isolated agent and has a disposable clone plus isolated caches, scratch outputs and reproduction checkout. At most three experiments occupy slots across planning handoff, implementation, testing, execution, review, persistence and cleanup. Record blocked and failed outcomes with their evidence. After the terminal candidate is pushed and verified, confirm every required file and irreplaceable observation is durable. The parent checks a clean remote checkout and authorizes cleanup. Confirm remote availability and absence of experiment-owned paths before reusing the slot.

Each experiment's work plan supplies its objectives, formal model, controls and evidence gates. Its execution record tracks scope, source reconstruction, implementation and run ledgers, failures, independent checks, deviations, results, persistence and handoff. The final orchestration report consolidates all terminal results and the evidence matrix.
