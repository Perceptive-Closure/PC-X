# EXP-X16 common executable interface

The public JSON catalogue contains `profiles`. A profile has a layered graph, `start`, allowed `accept` vertices, `initial_meter`, work `deadline`, move `horizon` and a named `variant`. Indices `stage` are zero-based. Edges have globally unique IDs within a profile, tail/head, `stale` (0 or 1) and nonempty `gives`, each a full supported `{"obs","meter"}` object. Each stage has a task, positive integer base and premium, online `reads` keyed by current public meter then literal command, and total pure predeployment `statics`. A statics field `stale` answers `fresh` or `stale`. Field `edge` answers the actual edge ID. Quote keys and branch observation strings never contain `|`.

## Standard commands and guards

`job.fast` normally costs the base, `job.slow` base plus premium, both zero paid charge. Each completes the current actual stage and advances exactly once. The fast source atom refreshes a stale representation relation on at least its last supported branch. On earlier branches of the same stale occurrence the relation may be unchanged. An R freeze removes the **full occurrence** if any supported successor changes that equivalence. All fresh fast and all slow outcomes preserve R. Each listed job receipt is supported; exposing one requires completed authorized stage work. The declared stages transform and durably receipt a synthetic input document. `job.slow` is the common refuge; a deliberate split-calls control uses an edge's `literal_fast` public command.

A `reads[meter][id]` row gives paid `price`, `observe` (`stale` means fresh/stale answer, `prepared` means the literal answer prepared) and `next` meter (`same` means unchanged). Reads use zero work, do not advance the installed path or change the document in the standard variants. No other command is available. A visible branch key is exactly `obs|meter`. An initial record normally has `{"obs":"start","meter":initial_meter}`. `free-guard` instead visibly discloses whether the second-stage bit is fresh. In `hidden-carry`, a prior edge with `carry:true` adds 4 to the later `ask.flag` native paid quote without any preceding change to the observed meter. In `changed-instrument`, a native `ask.flag` result still has its standard response and quote, but affects the eventual destination to a known wrong local path named `quarantine`. The two abstract-only controls leave the native catalogue standard.

The authoritative JSON seal is `{schema:1,catalogue_sha256,source_commit,frozen_manifest_sha256,public_key_pem,signature}`. Ed25519 verifies the signature byte string `PCX-X16-authority-v1 followed by LF` followed by catalogue SHA-256, source commit SHA and frozen manifest SHA-256, each followed by LF. `signature` encodes detached bytes in Base64. Runtime checks actual catalogue bytes against this SHA. The independently retrieved freeze/release pins establish authoritative identity of the public key. No secret key is in the source tree.

## Batch native CLI

`node service/native.mjs request.json response.json` takes an object with absolute `catalogue`, `authority`, `workspace` and a `tasks` array. The workspace is an explicitly selected generated local directory for case artifacts. The output is `{results:[...]}` in task order. No network calls, native user commands or work outside the supplied sandbox are needed. Each task has `id`, `profile` and `path` (actual accepting edge IDs); the actual path is never in a planner input.

- `op:"inventory"`: returns `initial:{stage:0,obs,meter}` and `rows` for all stage/meter pairs relevant to this path. A row has `{stage,edge,meter,commands:[...]}`. A command gives literal `id`, `kind:"job"|"read"`, `enabled`, `allowed`, `work`, `paid` and full ordered `outcomes:[{obs,meter,r_changed}]`, including the raw support of a freeze-removed atom. If an atom is freeze-removed its raw outcomes are still listed. Preserve actual quote/receipt and any earlier history effects. Only rows with prior task obligations met are described. No forecast uses this installed diagnostic interface.
- `op:"static"`: also has `queries` (in treatment order), returns `answers` keyed by requested static ID, `paid` paid total. These queries are authorized only to the declared comparator.
- `op:"run"`: adds synthetic `document:{id,title,category,body}`, `policy`, and optional `tape:[0,1,...]` indices (each move chooses its own position in the source outcome row, default 0). Policy is a JSON tree with nodes `{act:"...",next:{"obs|meter":node}}` or `{verdict:"YES"|"NO"}`. A diagnostic manual path can use `actions:[...]` instead of a tree, and the driver stops at end of list. The run returns `initial`, `status` (`"stopped"`, `"denied"`, `"missing-branch"`, `"horizon"`, or `"manual-done"`), `verdict` or null, `steps` with `{act,stage,meter,obs,next_meter,work,paid,artifact}` where `artifact` is a relative durable record or null, plus top-level totals `work`, `paid`, `moves`, and `truth:{complete,done,expected_destination,actual_destination,artifact_paths,document_sha256}`. Every record can be read directly under the run subdirectory in the supplied workspace. Stage outputs carry actual input and prior-output digests, phase/task and work product. The native encoder documents its deterministic SHA-256 and content format for independent external checking. AUTHORIZED outcomes are chosen from enumerated source rows after checking whole-action legality and residual work. `truth.complete` depends on actual meaningful persisted work and correct destination, not on the policy labelling YES. The native authority interface and durable work checks may include extra evidence fields.

Native diagnostics and raw truth fields are available to the independent instrumentation and direct comparators. Only `status`, genuine receipt and public declared quote/cost observations feed online policy execution. Control mismatches are disclosed separately with concrete row/artifact evidence. Native test harness must permit local training with an obviously dummy source seal and sandbox and avoid any held-out value.
